# 注册登录 + 个人中心（收藏 / 申请）手工测试清单

## 1. 测试目标

覆盖以下链路：

- 注册
- 登录 / 退出
- 帖子详情页收藏
- 帖子详情页发送申请
- 个人中心 `我的收藏`
- 个人中心 `我的申请`
- 个人中心 `收到申请`
- 申请状态流转与未读清零

本清单按当前代码实现编写，测试时请以实际页面和数据库结果同时作为判定依据。

## 2. 测试前准备

### 环境准备

- 项目已可通过浏览器访问，例如：
  - `http://localhost/hk-rentmatch/register.php`
  - `http://localhost/hk-rentmatch/login.php`
  - `http://localhost/hk-rentmatch/profile.php`
- 数据库已导入并能通过 MySQL 客户端或 phpMyAdmin 查询
- 使用全新注册账号进行测试，不使用 `database.sql` 中的示例账号

### 测试账号

准备以下 2 个账号：

- 学生账号 A
  - 用于收藏、申请、查看“我的申请”
- 房东账号 B
  - 用于验证“不可收藏 / 不可申请”
  - 用于查看“收到申请”并处理申请

### 测试帖子

至少准备 1 条 `active` 状态帖子，且满足：

- 帖子拥有者不是学生账号 A
- 最好由房东账号 B 发布，便于完整验证“收到申请”

建议记录以下信息，便于 SQL 核对：

- 学生账号 A 的邮箱 / 用户 ID
- 房东账号 B 的邮箱 / 用户 ID
- 测试帖子 ID

## 3. 业务规则速记

当前代码中的关键规则如下：

- 注册页只接受 `student` 和 `landlord`
- 注册页性别只允许 `male` / `female`
- 学生注册时学校必填，房东注册时学校可为空
- 学校下拉应覆盖香港本地 22 所颁授学位院校，包含常见自资院校
- 电话必须为香港本地 8 位号码，且首位为 `2-9`
- 密码长度必须为 8-20 位，且同时包含大写字母、小写字母、数字
- 注册成功后会自动登录并跳转首页
- 登录成功后跳转首页
- 未登录访问 `profile.php` 会被重定向到首页登录引导
- 只有 `student` / `admin` 可以收藏和申请
- `landlord` 不可收藏和申请
- 不允许申请自己的帖子
- 同一用户对同一帖子不能同时存在两条 `pending` 申请
- 打开 `profile.php?section=received` 会清空该房东收到申请的 `owner_unread`
- 打开 `profile.php?section=applications` 会清空该申请人的 `applicant_result_unread`

## 4. 执行清单

### A. 注册

#### A1. 学生注册成功

- [ ] 打开 `register.php`
- [ ] 选择身份为 `港硕学生`
- [ ] 填写合法学校、昵称、性别、邮箱、8 位电话、合法密码、确认密码
- [ ] 提交后成功跳转首页
- [ ] 页面顶部显示已登录状态
- [ ] 数据库中该用户 `role='student'`
- [ ] 数据库中该用户 `school` 非空
- [ ] 数据库中该用户 `status='active'`

#### A2. 房东注册成功

- [ ] 退出当前登录
- [ ] 再次打开 `register.php`
- [ ] 选择身份为 `房源供给方`
- [ ] 学校留空，其余字段合法
- [ ] 提交后成功跳转首页
- [ ] 页面顶部显示已登录状态
- [ ] 数据库中该用户 `role='landlord'`
- [ ] 数据库中该用户 `school` 可为空
- [ ] 数据库中该用户 `status='active'`

#### A3. 注册校验失败

- [ ] 学生身份未选择学校时提交失败
- [ ] 房东身份下学校可留空并能提交成功
- [ ] 昵称少于 2 位时提交失败
- [ ] 昵称超过 20 位时提交失败
- [ ] 昵称为空时提交失败
- [ ] 性别未选时提交失败
- [ ] 邮箱为空时提交失败
- [ ] 邮箱格式错误时提交失败
- [ ] 电话为空时提交失败
- [ ] 电话不是 8 位数字时提交失败
- [ ] 电话首位为 `0` 或 `1` 时提交失败
- [ ] 电话包含空格、横杠或字母时提交失败
- [ ] 密码为空时提交失败
- [ ] 密码少于 8 位时提交失败
- [ ] 密码超过 20 位时提交失败
- [ ] 密码缺少大写字母时提交失败
- [ ] 密码缺少小写字母时提交失败

#### A4. 观察项

- [ ] 学校下拉中除 `HKU / CUHK / HKUST / CityU / PolyU / HKBU / LU / EdUHK` 外，还应能看到 `HKMU / HKSYU / HSUHK / TWC / SFU / HKCT / UOWCHK / YCCECE` 等院校
- [ ] 随机抽查至少 1 所非八大院校完成学生注册，例如 `香港都会大学 HKMU` 或 `香港恒生大学 HSUHK`
- [ ] 对已注册邮箱重复提交后，页面应提示邮箱已注册，数据库中同邮箱记录数仍为 `1`
- [ ] 学生提交申请后，房东进入 `profile.php?section=received` 能看到该申请
- [ ] 当前实现不接受 `other` 性别；若课程需求要求三种性别，登记为“需求/实现不一致”

### B. 登录 / 退出

#### B1. 正常登录

- [ ] 打开 `logout.php`，确保当前退出
- [ ] 使用学生账号 A 在 `login.php` 输入正确邮箱和密码
- [ ] 登录成功并跳转首页

#### B2. 登录失败

- [ ] 邮箱格式错误时登录失败
- [ ] 密码留空时登录失败

- [ ] 使用不存在邮箱登录失败

#### B3. 退出

- [ ] 登录后访问 `logout.php`
- [ ] 再访问 `profile.php`
- [ ] 页面不应直接进入个人中心，应跳回登录引导

### C. 收藏

#### C1. 未登录时收藏入口

- [ ] 未登录打开测试帖子详情页 `post/detail.php?id=<帖子ID>`
- [ ] 页面显示“登录后收藏”
- [ ] 无法直接执行收藏

#### C2. 学生收藏成功

- [ ] 使用学生账号 A 登录

- [ ] 按钮变为“已收藏”

- [ ] 收藏列表中可看到该帖子

#### C3. 学生取消收藏

- [ ] 在详情页再次点击收藏按钮，或在 `我的收藏` 中点击“取消收藏”
- [ ] 页面提示取消成功
- [ ] `favorites` 表对应记录被删除

#### C4. 房东不可收藏

- [ ] 使用房东账号 B 登录并打开测试帖子详情页

- [ ] 打开 `profile.php?section=favorites`

#### C5. 收藏筛选

- [ ] 在 `我的收藏` 中切换 `全部 / 租房 / 找室友 / 转租`
- [ ] 当前数据量允许时，各筛选结果与帖子类型一致

#### C6. 重复收藏

- [ ] 对同一帖子重复收藏不会生成重复数据
- [ ] `favorites` 表中同一 `user_id + post_id` 最多只有 1 条记录

### D. 申请

#### D1. 未登录时申请入口

- [ ] 未登录打开测试帖子详情页
- [ ] 页面显示“登录后申请”
- [ ] 无法直接发送申请

#### D2. 学生发送申请成功

- [ ] 使用学生账号 A 登录
- [ ] 打开他人 `active` 帖子详情页
- [ ] 输入 1-500 字合法留言
- [ ] 点击提交申请
- [ ] 页面提示申请发送成功
- [ ] `applications` 表新增记录

- [ ] 新记录 `owner_unread=1`
- [ ] 新记录 `applicant_result_unread=0`

#### D3. 申请失败场景

- [ ] 申请自己的帖子时失败

#### D4. 房东不可申请

#### D5. 学生撤回申请

- [ ] 在 `我的申请` 中对 `pending` 申请点击“撤回”

### E. 收到申请 / 状态流转

#### E1. 房东收到未读申请

- [ ] 学生 A 成功发送一条新的 `pending` 申请
- [ ] 房东 B 在进入 `received` 前侧边栏出现未读角标
- [ ] 数据库中该申请 `owner_unread=1`

#### E2. 进入 received 后清除房东未读

- [ ] 房东 B 打开 `profile.php?section=received`
- [ ] 页面可看到该申请

#### E3. 房东同意申请

- [ ] 对 `pending` 申请点击“同意”
- [ ] 页面提示处理成功

- [ ] 数据库中该申请 `applicant_result_unread=1`

- [ ] 同一申请不再显示“同意 / 拒绝”按钮

#### E4. 学生查看同意结果

- [ ] 学生 A 登录后，侧边栏应看到“我的申请”未读角标
- [ ] 打开 `profile.php?section=applications`
- [ ] 数据库中该申请 `applicant_result_unread=0`

#### E5. 房东拒绝申请

- [ ] 数据库中该申请 `applicant_result_unread=1`

- [ ] 数据库中该申请 `applicant_result_unread=0`
- [ ] 页面状态显示“已拒绝”

## 5. 通过标准

以下条件全部满足时，可判定本模块主流程通过：

- 注册、登录、退出流程可用
- 学生可收藏 / 申请，房东不可收藏 / 申请
- 收藏无重复记录
- 申请状态仅按 `pending -> accepted / rejected / withdrawn` 流转
- `我的收藏`、`我的申请`、`收到申请` 与数据库结果一致
- 房东未读与申请人结果未读逻辑符合数据库字段变化
- 接受申请后双方可见联系方式，拒绝申请后不展示成功联系信息
